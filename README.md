# KeyCraft — интерактивный интернет-магазин на JavaScript

## Контрольная работа №4

Тема: «JavaScript: интерактивность, DOM, события, формы и валидация».

## Основа проекта

Проект создан на основе КР №3 — адаптивной версии сайта [kr3-responsive-shop](https://github.com/Kurligin/kr3-responsive-shop). Адаптивная вёрстка, доступность и фото товаров перенесены из неё. Bootstrap не используется, JavaScript — без библиотек.

Что изменилось по сравнению с КР №3:

- карточки товаров больше не написаны вручную в HTML: их создаёт JavaScript по массиву товаров;
- товаров стало 10 вместо 6;
- добавлены поиск, фильтры и сортировка, корзина, избранное и промокоды;
- страница товара собирается по адресу `product.html?id=N`.

## Ссылка на опубликованный проект

GitHub Pages: https://kurligin.github.io/kr4-js-shop/

## Как запустить

1. Открыть опубликованную версию или склонировать репозиторий.
2. Открыть `index.html` в браузере. Сборка и установка зависимостей не нужны.

Корзина и избранное сохраняются в `localStorage`, поэтому для проверки сохранения лучше открывать сайт по адресу (GitHub Pages или Live Server), а не как файл.

## JavaScript-файлы

Скрипты подключаются обычными тегами `<script defer>` в `<head>`. Атрибут `defer` выполняет их по порядку после разбора HTML. Порядок важен: каждый следующий файл пользуется функциями предыдущих.

| Файл | За что отвечает |
| --- | --- |
| `data.js` | массив товаров `products` и словарь подписей категорий `categories` |
| `product-utils.js` | чистые функции обработки данных: цена, скидка, статус, поиск, фильтр, сортировка, подсчёты |
| `storage.js` | безопасное чтение и запись `localStorage` (`JSON.parse` в `try/catch`) |
| `favorites.js` | состояние избранного и его сохранение |
| `cart.js` | состояние корзины, расчёт суммы через `reduce`, промокоды, доставка, вывод корзины и счётчик в шапке |
| `catalog.js` | создание карточек через `createElement`, каталог с поиском, фильтрами и сортировкой, популярные и рекомендуемые товары, делегирование кликов |
| `product-page.js` | сборка страницы товара по `id` из адреса, таблицы характеристик и сравнения, отзывы, похожие товары |
| `modal.js` | модальное окно быстрой заявки и консультации |
| `validation.js` | проверка всех форм, вывод ошибок под полями, маска телефона, имитация отправки |
| `main.js` | общие действия: мобильное меню, раскрытие фильтров, всплывающие уведомления |

Все файлы подключены на всех страницах. Каждый блок начинается с проверки, есть ли нужный элемент на странице, например `if (productsContainer) { ... }`. Поэтому скрипт не падает там, где этого элемента нет.

Одна функция объявлена в одном файле. Например, `searchProducts` и `formatPrice` живут только в `product-utils.js`, и одноимённые функции разных версий не перекрывают друг друга.

## Массив товаров

В `js/data.js` 10 товаров четырёх категорий: клавиатуры, свитчи, кейкапы, аксессуары. У всех товаров одинаковая структура:

```js
{
  id: 2,                       // уникальный номер
  title: 'KeyCraft TKL Pro',
  category: 'keyboards',       // совпадает со значением option в фильтре
  price: 11990,                // число, а не строка
  discountPercent: 10,
  rating: 4.8,
  isAvailable: true,
  isPopular: true,             // показывать на главной
  badge: '',                   // 'hit', 'new', 'soon' или пусто
  image: 'keyboard-tkl',       // основа имени файла фото
  description: '...',
  features: ['...'],           // список преимуществ на странице товара
  specs: { 'Корпус': 'Алюминий' },
  reviews: [{ author, rating, date, text }],
}
```

Цены записаны числами, поэтому их можно сравнивать при сортировке и складывать в корзине. В строку цена превращается только при выводе — функцией `formatPrice`.

## Реализованные функции

**Практическая работа №15** — переменные, типы, функции (`product-utils.js`):

- `formatPrice(price)` — `11990` → `11 990 руб.`;
- `calculateDiscount(price, discountPercent)` — размер скидки в рублях;
- `calculateFinalPrice(price, discountPercent)` — цена со скидкой;
- `getProductStatus(product)` — «В наличии» или «Нет в наличии»;
- `createProductSummary(product)` — строка для описания страницы товара и блока статистики.

**Практическая работа №16** — массивы и методы массивов:

- `getProductTitles` — `map`;
- `getAvailableProducts` — `filter`;
- `findProductById` — `find`;
- `calculateTotalPrice` — `reduce`;
- `countAvailableProducts`, `calculateAveragePrice`;
- `searchProducts`, `filterProductsByCategory`, `sortProducts`, `getPreparedProducts`.

**Практическая работа №17** — DOM и события:

- `createProductCard`, `renderProductList`, `updateCatalog` (`catalog.js`);
- `showError`, `clearError`, `validateName`, `validateEmail`, `validatePhone` (`validation.js`).

Блок «Каталог в цифрах» внизу каталога — учебный блок проверки JavaScript из ПЗ №15–16 (`.js-message` и `.product-output`). Он выводит через `textContent` статистику, посчитанную функциями по массиву товаров.

## Поиск

Поле `#catalog-search`, событие `input`. Список обновляется при каждом нажатии клавиши, без кнопки «Найти».

```js
const normalizedQuery = query.trim().toLowerCase();
return products.filter((product) => product.title.toLowerCase().includes(normalizedQuery));
```

`trim()` убирает случайные пробелы, а `toLowerCase()` делает поиск нечувствительным к регистру: «RED» найдёт «Linear Red».

## Фильтрация

- **Категория** — `#category-filter`, событие `change`. Значение `all` показывает все товары, иначе `filter` по `product.category`.
- **«Только в наличии»** — чекбокс `#only-available`.
- **«Только избранное»** — чекбокс `#only-favorites`.

Все условия хранятся в объекте `catalogState`. После любого изменения вызывается `updateCatalog()`: он прогоняет массив через `getPreparedProducts` (поиск → категория → наличие → избранное → сортировка) и перерисовывает карточки.

Категория и поисковый запрос попадают в адрес страницы, например `catalog.html?category=switches`. Так ссылки из подвала открывают каталог сразу на нужной категории. Значение из адреса принимается только из списка известных категорий.

## Сортировка

`#sort-select`, событие `change`. Варианты:

- по умолчанию;
- сначала дешевле;
- сначала дороже;
- по названию А–Я (`localeCompare`);
- по рейтингу.

Сортировка по цене учитывает скидку: сравнивается цена, которую покупатель заплатит.

Сортируется копия массива `[...products]`, потому что `sort()` меняет массив, на котором вызван. Если сортировать исходный `products`, после выбора «По умолчанию» исходный порядок уже не вернуть.

## Пустое состояние

Если ничего не нашлось, вместо карточек появляется блок «Ничего не нашлось»:

- в нём показан запрос пользователя — через `textContent`;
- кнопки быстрого перехода в категории;
- кнопка «Сбросить все фильтры».

Над списком всегда видно «Найдено товаров: N из 10». У этой строки `aria-live="polite"`, поэтому экранный диктор сообщает результат.

## Валидация форм

Проверяются все три формы: заявка на `order.html`, обратная связь на `contacts.html` и быстрая заявка в модальном окне.

- Каждое поле получает правило через атрибут `data-validate`: `name`, `email`, `phone`, `required`, `agreement`, `message`, `date`.
- При отправке `preventDefault()` останавливает перезагрузку, затем проверяются все поля сразу.
- Ошибка выводится через `textContent` в `<p class="form-error">` под полем. Поле получает `aria-invalid="true"`, а связь с текстом ошибки задана через `aria-describedby`.
- Над кнопкой появляется общее сообщение «Проверьте поля формы: ошибок — N», фокус переходит на первое ошибочное поле.
- После исправления ошибка исчезает сразу. Пока поле не трогали, ошибки не показываются.

Правила проверки:

| Поле | Правило |
| --- | --- |
| имя | не короче 2 символов |
| e-mail | шаблон `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` |
| телефон | 11 цифр, начинается с 7 или 8; код оператора или города начинается с 3, 4, 8 или 9. 10 цифр тоже принимаются: считается, что код страны +7 |
| дата связи | не раньше сегодняшнего дня |
| сообщение | не короче 10 символов |
| выпадающие списки и согласие | обязательны |

`alert()` в проекте не используется.

## Безопасный вывод данных

Все данные выводятся через `textContent`, а элементы создаются через `createElement`. Это касается:

- названий товаров;
- поискового запроса в пустом состоянии;
- данных из `localStorage` и параметров адреса;
- сообщений формы.

`innerHTML` в проекте не используется ни разу.

**Почему так.** `innerHTML` разбирает строку как HTML. Если в неё попадёт пользовательский ввод вроде `<img src=x onerror=...>`, браузер выполнит чужой код. `textContent` всегда вставляет строку как обычный текст, и теги в ней остаются просто символами.

Поэтому в пустом состоянии каталога запрос `<b>тест</b>` показывается буквально, а не жирным шрифтом.

## Самостоятельные доработки

**Корзина (`cart.js`, `cart.html`)**

- Добавление из каталога, с главной, со страницы товара и из «Похожих товаров».
- Счётчик в шапке на всех страницах.
- На странице корзины:
  - кнопки «+» и «−», не больше 10 штук одного товара;
  - удаление позиции и очистка всей корзины;
  - после изменения фокус остаётся на нажатой кнопке.
- Расчёт через `reduce`:
  - сумма без скидок;
  - скидка на товары;
  - скидка по промокоду;
  - доставка: 390 руб., бесплатно от 5 000 руб., с подсказкой, сколько осталось до бесплатной;
  - итог.
- Промокоды:
  - `KEYCRAFT10` — скидка 10%;
  - `SWITCH500` — минус 500 руб. при сумме от 3 000 руб.;
  - понятные сообщения, если код неверный или сумма слишком мала;
  - промокод можно отменить.
- Корзина и промокод сохраняются в `localStorage`.
  - При загрузке каждая позиция проверяется: товар существует, есть в наличии, количество от 1 до 10.
  - Испорченная запись не ломает страницу.
- «Оформить заказ» ведёт на `order.html?from=cart`:
  - вместо выбора товара там показан состав корзины с итоговой суммой;
  - после отправки корзина очищается.
- Пустая корзина показывает подсказку и ссылку в каталог. Блок «Вам может понравиться» предлагает товары с высоким рейтингом, которых ещё нет в корзине.

**Избранное (`favorites.js`)**

- Кнопка-сердечко на каждой карточке и на странице товара.
- `aria-pressed` сообщает экранному диктору, нажата ли кнопка.
- Избранное сохраняется в `localStorage`. В каталоге есть фильтр «Только избранное».

**Страница товара (`product-page.js`)**

- Одна страница `product.html` показывает любой товар по `?id=N`:
  - название и заголовок вкладки;
  - фото с `srcset`;
  - бейдж;
  - рейтинг;
  - цена со скидкой и экономия;
  - характеристики из объекта `specs`;
  - отзывы;
  - «Похожие товары» той же категории.
- Таблица сравнения клавиатур строится из массива и показывается только у клавиатур. На телефоне она, как в КР №3, превращается в карточки.
- Для несуществующего `id` выводится «Товар не найден» со ссылкой в каталог.

**Улучшенные карточки**

- Бейджи «Хит», «Новинка», «Скоро в продаже» и «−10%».
- Старая цена зачёркнута, новая выделена. Для экранного диктора добавлены скрытые подписи «Старая цена» и «цена со скидкой».
- Рейтинг, категория, статус наличия.
- Отключённая кнопка «Недоступно» у товаров, которых нет в наличии.

**Формы**

- Имитация отправки:
  - кнопка блокируется и меняет текст на «Отправляем…»;
  - через 0,8 секунды появляется сообщение с номером заявки, например `KC-123456`;
  - форма очищается.
- Маска телефона: при уходе с поля номер приводится к виду `+7 (900) 123-45-67`, каким бы способом его ни ввели.
- Модальное окно:
  - «Купить в один клик» на странице товара и «Получить консультацию» на главной;
  - Esc и клик по фону закрывают окно;
  - фокус возвращается на кнопку.

**Интерфейс**

- Всплывающее уведомление с `role="status"` после добавления в корзину и избранное: и видно, и озвучивается диктором.
- Ссылки из подвала ведут сразу в нужную категорию каталога.
- Без JavaScript вместо пустого каталога показывается сообщение в `<noscript>`.

**Проверка**

- Lighthouse Accessibility — 100 на всех шести страницах.
- Горизонтальной прокрутки нет на ширинах 360, 430, 768, 1024 и 1440 px.

## Как проверить

1. **Каталог.**
   - Ввести «red» — останется «Набор свитчей Linear Red».
   - Ввести «zzz» — появится пустое состояние. Нажать в нём «Кейкапы».
2. **Категория и сортировка.** Выбрать «Свитчи», сортировку «Сначала дешевле» — три набора по возрастанию цены. Адрес станет `catalog.html?category=switches`.
3. **Корзина.**
   - Нажать «В корзину» у KeyCraft TKL Pro дважды — счётчик в шапке станет 2.
   - Открыть корзину: сумма, скидка 10%, бесплатная доставка.
   - Ввести промокод `KEYCRAFT10`.
   - Перезагрузить страницу — всё сохранилось.
4. **Заказ из корзины.** Нажать «Оформить заказ», заполнить форму и отправить. Корзина очистится.
5. **Пустая форма.** На `order.html` отправить пустую форму — 6 ошибок под полями. Ввести телефон `89001234567` и перейти к следующему полю — номер отформатируется.
6. **Несуществующий товар.** Открыть `product.html?id=999` — «Товар не найден».
7. **Консоль.** В DevTools → Console на всех страницах нет ошибок. В Application → Local Storage видны ключи `keycraft-cart`, `keycraft-favorites` и `keycraft-promo`.
